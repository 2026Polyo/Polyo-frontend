# Polyomino 와이어프레임 / UI·UX 평가

## 1. 평가 요약

현재 와이어프레임은 **게임의 핵심 행동인 "블록 선택 -> 보드 배치 -> 점수/보상 확인"을 비교적 잘 유도하는 구조**입니다. 시작 화면은 바로 플레이로 들어갈 수 있고, 플레이 화면은 중앙 보드와 하단 트레이를 중심으로 구성되어 있어 퍼즐 게임의 주 행동이 명확합니다.

다만 장기 플레이 UX 관점에서는 다음 문제가 큽니다.

- 파란색 계열 표면이 너무 많아 보드, 패널, 버튼의 중요도 차이가 약해집니다.
- 좌측 증강, 우측 아이템/덱, 상단 점수, 중앙 보드의 정보량이 많아 첫 진입자가 현재 목표를 한눈에 파악하기 어렵습니다.
- 일부 상호작용은 마우스/호버 중심이라 모바일·키보드 접근성에서 불편이 생길 수 있습니다.
- 모달은 보상 선택 자체는 명확하지만, "왜 지금 이 선택을 해야 하는지"와 "선택 후 무엇이 달라지는지"의 설명 위계가 더 강해야 합니다.

종합 점수: **7.2 / 10**

| 항목 | 점수 | 판단 |
| --- | ---: | --- |
| 핵심 게임 행동 유도 | 8 | 보드와 트레이 중심 구조가 좋음 |
| 한눈에 보는 정보 위계 | 6 | 보조 패널과 CTA의 우선순위가 비슷하게 보일 위험 |
| 조작 편의성 | 7 | 클릭/드래그 흐름은 좋지만 터치·키보드 보완 필요 |
| 피드백/보상감 | 8 | 점수, 콤보, 클리어, 보상 모달 피드백이 충분함 |
| 반응형 안정성 | 6 | 큰 화면은 좋고, 작은 화면은 보조 패널 밀도가 부담 |
| 접근성 | 6 | ARIA는 일부 적용되어 있으나 포커스, 모달, 키보드 조작 보완 필요 |
| 시각 완성도 | 7 | 밝고 게임답지만 단색 계열이 강함 |

## 2. 평가 기준

이번 평가는 다음 UI/UX 규칙으로 판단했습니다.

- **시선 흐름**: 플레이어가 가장 먼저 봐야 할 목표와 행동이 눈에 들어오는가.
- **행동 유도성**: 다음에 눌러야 할 버튼, 선택해야 할 블록, 배치 가능 위치가 분명한가.
- **피드백**: 선택, 배치 가능/불가능, 점수 획득, 보상, 실패 상태가 즉시 보이는가.
- **인지 부하**: 한 화면의 정보량이 게임 판단을 방해하지 않는가.
- **오류 예방**: 실수 조작, 잘못된 배치, 덱 구성 실패를 미리 막거나 회복할 수 있는가.
- **접근성**: 키보드, 스크린리더, 터치 환경에서도 핵심 흐름이 막히지 않는가.
- **반응형**: 모바일과 데스크톱 모두에서 보드, 트레이, CTA가 안정적으로 보이는가.

## 3. 전체 정보 구조 평가

### 현재 구조

```text
Start
└─ Polyomino 타이틀
   ├─ 이어하기
   ├─ 새 게임
   ├─ 덱 구성
   └─ Best / 진행 점수

Play
├─ 좌상단 Best
├─ 상단 현재 점수 / 예상 획득 점수
├─ 좌측 증강 패널
├─ 중앙 8x8 보드
├─ 하단 블록 트레이
├─ 우측 아이템 패널
├─ 우측 덱 보기 버튼
└─ 설정 / 보상 / 증강 / 리롤 / 게임오버 모달
```

### 좋은 점

- 중심 플레이 영역이 보드와 트레이로 명확합니다.
- 시작 화면은 바로 이어하기/새 게임/덱 구성으로 갈라져 진입 흐름이 짧습니다.
- 플레이 화면은 반복 행동에 필요한 요소가 모두 같은 화면에 있어 페이지 이동이 거의 없습니다.
- 보상, 증강, 리롤, 게임오버를 모달로 분리해 플레이 흐름을 끊어야 하는 순간을 명확히 만듭니다.

### 약한 점

- 플레이 화면에 보조 시스템이 많습니다. 증강, 아이템, 덱, 설정, 최고점, 예상 점수가 동시에 보여 초반 플레이어가 어디를 봐야 할지 흔들릴 수 있습니다.
- `덱 보기` 버튼이 우측 패널 영역에 있고 세로형 큰 버튼이라, 아이템만큼 중요한 행동처럼 보입니다. 실제 핵심 루프에서는 덱 보기가 보조 기능이면 시각 무게를 줄이는 편이 좋습니다.
- 증강 패널은 장기 성장 정보를 보여주지만, 현재 턴 의사결정에는 대부분 보조 정보입니다. 보드보다 시각 경쟁력이 높아지면 집중을 빼앗습니다.

## 4. 화면별 와이어프레임 평가

## 4.1 시작 화면

### 현재 의도

시작 화면은 `Polyomino` 브랜드, 블록 미리보기, 이어하기, 새 게임, 덱 구성, 최고 점수를 보여줍니다.

### 평가

좋습니다. 시작 화면의 목적은 "계속할지, 새로 시작할지, 덱을 바꿀지" 세 가지이고 현재 구조가 그 목적에 맞습니다. 블록 미리보기는 장르를 즉시 알려주는 장치라 타이틀만 있는 화면보다 낫습니다.

### 위험

- 이어하기가 있을 때 `이어하기`, `새 게임`, `덱 구성`이 모두 비슷한 버튼 묶음으로 보이면 초보자는 무엇이 추천 행동인지 헷갈릴 수 있습니다.
- 새 게임이 비활성화될 때 조건 설명은 `title`/`aria-label`에 있지만, 모바일에서는 title을 보기 어렵습니다.

### 개선

1. 이어하기가 가능하면 `이어하기`를 가장 강한 CTA로 유지하고, `새 게임`은 낮은 강조로 둡니다.
2. 새 게임 비활성 조건은 버튼 아래 짧은 고정 문구로 보여주는 편이 모바일에 안전합니다.
3. 덱 구성은 "시작 전 설정" 성격이므로 CTA보다 작은 보조 버튼으로 유지합니다.

권장 와이어프레임:

```text
[블록 미리보기]
POLYOMINO

[이어하기]        <- 저장 게임이 있으면 1순위
[새 게임]
[덱 구성]

Best 0000
```

## 4.2 플레이 화면

### 현재 의도

플레이 화면은 중앙 보드를 중심으로, 하단 트레이에서 블록을 선택하고 보드에 배치하는 구조입니다. 좌측은 증강, 우측은 아이템과 덱 보기, 상단은 점수입니다.

### 평가

핵심 구조는 좋습니다. 퍼즐 게임에서는 보드가 가장 커야 하고, 다음 행동인 트레이가 보드 바로 아래에 있어야 합니다. 현재 와이어프레임은 이 원칙을 지킵니다.

### 위험

- 데스크톱 3열 구조는 넓은 화면에서 보기 좋지만, 보조 패널이 보드와 같은 높이에 있어 시각 경쟁이 생깁니다.
- 모바일 또는 중간 폭에서는 증강/아이템/덱 버튼이 보드 위아래로 재배치되며 핵심 플레이 시작 전에 보조 정보가 먼저 보일 수 있습니다.
- 선택한 조각을 따라다니는 커서 방식은 마우스에는 좋지만 터치에서는 현재 선택 상태와 취소 방법이 더 명확해야 합니다.

### 개선

1. 보드는 항상 첫 번째 시각 중심이어야 합니다. 보조 패널은 보드보다 명도/그림자/크기를 낮춥니다.
2. 모바일에서는 `점수 -> 보드 -> 트레이 -> 아이템 -> 증강 요약 -> 덱` 순서가 좋습니다.
3. 증강은 기본 접힘 또는 한 줄 요약으로 두고, 상세는 탭/터치 시 확장합니다.
4. 덱 보기는 큰 세로 버튼보다 작은 아이콘 버튼 또는 보조 버튼이 적절합니다.

권장 와이어프레임:

```text
Desktop
┌────────────┬────────────────────┬────────────┐
│ 증강 요약   │      Score         │ 아이템      │
│ 낮은 강조   │   8x8 Board        │ 3칸         │
│ 상세 hover  │   Piece Tray       │ 덱 보기     │
└────────────┴────────────────────┴────────────┘

Mobile
Score / Best
8x8 Board
Piece Tray
Item slots
Augment summary
Deck / Settings
```

## 4.3 보드와 배치 UX

### 좋은 점

- 보드 셀은 버튼으로 구성되어 클릭 가능한 영역이 명확합니다.
- 배치 미리보기, 클리어 예정 셀, 클리어 애니메이션이 분리되어 피드백 구조가 좋습니다.
- 예상 획득 점수 `+n`은 배치 결정을 돕는 좋은 정보입니다.

### 위험

- 셀의 `aria-label`이 "row/column" 중심이라 스크린리더에서는 실제 상태, 비어 있음, 배치 가능 여부를 충분히 전달하지 못합니다.
- 배치 불가능 상태는 커서 조각의 opacity 변화에 의존합니다. 색각/시각 조건에 따라 약할 수 있습니다.
- 보드 셀 hover 기반 미리보기는 터치 환경에서 약합니다.

### 개선

1. 불가능한 배치에는 빨간 outline 또는 흔들림 같은 명확한 피드백을 추가합니다.
2. 선택된 조각 상태를 트레이에도 계속 표시하고, 빈 트레이 클릭으로 선택 해제되는 흐름을 화면상으로 암시합니다.
3. 스크린리더용 상태 문구는 `빈 칸`, `채워진 칸`, `미리보기`, `클리어 예정`을 포함하도록 개선합니다.

## 4.4 조각 트레이

### 좋은 점

- 보드 바로 아래 3칸 트레이는 핵심 루프와 잘 맞습니다.
- 선택한 조각을 숨기고 커서 조각으로 옮기는 방식은 "지금 들고 있다"는 느낌을 줍니다.

### 위험

- 선택된 조각이 트레이에서 `visibility: hidden` 처리되면, 사용자가 취소 방법을 모를 때 빈칸처럼 느낄 수 있습니다.
- 빈 슬롯은 상호작용 의미가 상황에 따라 달라집니다. 선택 중이면 취소, 평상시에는 무의미합니다.

### 개선

1. 선택된 슬롯에는 완전 숨김보다 흐린 outline/placeholder를 남깁니다.
2. 선택 중 빈 슬롯에는 `선택 해제` 의미의 시각 힌트를 줍니다.
3. 터치에서는 선택 후 보드 상단에 작은 "배치할 위치를 선택" 상태 문구가 있으면 안전합니다.

## 4.5 점수와 보상 피드백

### 좋은 점

- 현재 점수가 화면 상단 중앙에 있어 게임 목표가 분명합니다.
- 예상 점수 `+n`, 점수 카운트업, combo/clear burst가 즉각적인 보상감을 줍니다.
- Best score가 고정 배지로 있어 장기 목표를 알려줍니다.

### 위험

- Best score가 좌상단 고정이고 설정이 우상단 고정이면 작은 화면에서 가장 중요한 현재 점수보다 주변 UI가 먼저 보일 수 있습니다.
- combo/clear burst는 강한 연출이므로 반복 플레이에서 피로해질 수 있습니다.

### 개선

1. 현재 점수를 최상위 정보로 유지하고, Best는 작은 보조 텍스트로 낮춥니다.
2. `prefers-reduced-motion` 대응을 추가해 burst/카운트업 움직임을 줄일 수 있게 합니다.
3. 점수 상승 원인(배치, 라인 클리어, 콤보)을 짧게 구분하면 학습성이 올라갑니다.

## 4.6 증강 패널

### 좋은 점

- 보유 증강을 아이콘 중심으로 압축해 공간 효율이 좋습니다.
- hover/focus 시 상세 패널이 나오는 구조는 숙련자에게 빠릅니다.
- `tabIndex`와 focus 처리가 있어 일부 키보드 접근을 고려했습니다.

### 위험

- 새 플레이어는 아이콘만 보고 증강 효과를 기억하기 어렵습니다.
- 모바일에서는 hover가 없으므로 상세 확인 방식이 약해질 수 있습니다.
- 8열 고정 그리드는 좁은 화면에서 아이콘이 작아지고 터치 타겟이 줄어들 수 있습니다.

### 개선

1. 모바일에서는 4열 또는 가로 스크롤 대신 접힌 요약 패널을 권장합니다.
2. 증강 개수가 적을 때는 "아직 증강 없음" 상태를 명확히 보여줍니다.
3. 상세 패널은 hover뿐 아니라 클릭/탭으로 고정되게 만듭니다.

## 4.7 아이템 패널

### 좋은 점

- 아이템 3칸이 명확하고, 아이콘/라벨/수량이 함께 있어 인지하기 쉽습니다.
- disabled 상태와 tooltip이 있어 사용 가능 여부를 어느 정도 설명합니다.

### 위험

- tooltip은 hover/focus에서는 좋지만 터치에서는 발견성이 낮습니다.
- undo 아이템이 불가능한 이유가 disabled만으로는 충분히 드러나지 않을 수 있습니다.
- 아이템 패널과 덱 버튼이 같은 우측 영역에서 비슷한 무게를 가지면 핵심 도구와 보조 정보가 섞입니다.

### 개선

1. 터치에서는 길게 누르기보다 탭으로 설명을 열 수 있게 합니다.
2. disabled 아이템에는 이유를 짧게 표시합니다. 예: `되돌릴 수 없음`.
3. 덱 보기 버튼은 아이템보다 낮은 강조로 조정합니다.

## 4.8 덱 구성 모달

### 좋은 점

- 현재 덱과 가진 블록을 좌우로 나누는 구조는 이해하기 쉽습니다.
- 선택 상태 check 표시가 명확합니다.
- 기본/특수 구분과 카운트가 있어 제한 조건을 확인할 수 있습니다.

### 위험

- "현재 덱 블록을 누르면 제거, 가진 블록을 누르면 추가"는 설명 문구를 읽어야 이해됩니다.
- disabled 블록이 왜 비활성인지 시각적으로 충분하지 않을 수 있습니다.
- 기본 블록을 여러 개 넣을 수 있는 규칙이 있다면 현재 UI가 "중복 가능/불가능"을 직관적으로 설명하지 못할 수 있습니다.

### 개선

1. 각 컬럼 상단에 `현재 덱`, `가진 블록`을 더 강하게 구분합니다.
2. 선택/비활성 이유를 tooltip보다 inline hint로 보여줍니다.
3. 모바일에서는 두 컬럼을 세로로 쌓되 `현재 덱`을 먼저 보여주는 현재 방향이 적절합니다.

## 4.9 증강/특수 보상 모달

### 좋은 점

- 3개 카드 중 1개 선택 구조는 보상 선택의 표준 패턴이라 명확합니다.
- 카드에 아이콘, 제목, 요약, 효과가 있어 선택 근거를 제공합니다.
- `new` 표시와 금색 강조는 새 보상감을 잘 줍니다.

### 위험

- 카드가 큰 9:16 비율이라 데스크톱에서는 시원하지만, 텍스트가 길어질 경우 카드 내부 밀도가 높아질 수 있습니다.
- 선택 후 되돌릴 수 없는지, 현재 빌드와 어떤 시너지가 있는지는 약합니다.

### 개선

1. 카드 하단 효과 문구를 가장 짧고 수치 중심으로 유지합니다.
2. 이미 가진 증강이면 현재 레벨과 증가분을 더 명확히 분리합니다.
3. 선택이 즉시 확정이면 카드 hover/focus 상태를 더 강하게 하고, 실수 방지용 짧은 확인은 필요 없습니다. 게임 속도상 확인 모달은 과합니다.

## 4.10 리롤 / 게임오버 / 설정

### 좋은 점

- 게임오버는 점수, Best, Retry, 홈으로가 명확합니다.
- 설정은 재시작/홈으로만 제공해 단순합니다.
- 리롤은 선택 단계와 결과 선택 단계가 분리되어 복잡한 기능을 단계화합니다.

### 위험

- 게임오버의 `Retry`와 `홈으로` 언어가 한영 혼합입니다. 전체 톤을 맞추는 편이 좋습니다.
- 설정에서 재시작은 파괴적 행동이므로 오조작 방지 확인이 필요할 수 있습니다.
- 리롤은 강화 레벨에 따라 모드가 달라져 초보자가 이해하기 어렵습니다.

### 개선

1. 버튼 언어를 한국어 중심 또는 영어 중심으로 통일합니다.
2. 설정의 재시작은 두 번 클릭 확인 또는 별도 확인 문구를 고려합니다.
3. 리롤 모달은 "1단계: 바꿀 블록 선택", "2단계: 새 블록 선택"처럼 단계 제목을 표시합니다.

## 5. 시각 디자인 평가

### 강점

- 하늘색/짙은 파란색 배경은 캐주얼 퍼즐 게임 분위기와 잘 맞습니다.
- 조각 색상은 cyan, lime, amber, rose, violet 등으로 다양해 보드 위 식별성이 좋습니다.
- 큰 점수, 금색 Best, 콤보 burst는 보상감을 잘 만듭니다.
- lucide 아이콘 사용으로 설정, 덱, 재시작, 홈 같은 행동이 빠르게 읽힙니다.

### 약점

- 페이지, 보드, 트레이, 아이템, 모달이 모두 파란 계열이라 깊이감은 있지만 정보 분리가 약합니다.
- radius가 전반적으로 커서 모든 UI가 비슷하게 둥글고 귀엽게 보입니다. 보드/트레이/모달/버튼의 역할 차이가 더 필요합니다.
- shadow가 여러 표면에 비슷하게 들어가면 중요도보다 장식감이 커질 수 있습니다.

### 개선 방향

1. **보드**: 지금처럼 가장 어둡고 무겁게 유지합니다.
2. **트레이/아이템**: 보드보다 약간 밝게, 그림자는 줄입니다.
3. **보조 패널**: 표면을 더 평평하게 만들어 보드와 경쟁하지 않게 합니다.
4. **CTA**: 시작/재시작/선택 확정만 강한 accent를 씁니다.
5. **덱 보기/설정**: 작은 아이콘 버튼으로 낮은 강조를 유지합니다.

## 6. 접근성 평가

### 현재 좋은 점

- 주요 모달에 `role="dialog"`와 `aria-modal="true"`가 있습니다.
- 여러 버튼에 `aria-label`이 들어가 있습니다.
- 증강 카드에는 focus 진입이 가능하도록 `tabIndex=0`이 있습니다.
- 아이템에는 `aria-describedby` tooltip 구조가 있습니다.

### 보완 필요

- 모달 열림 시 focus trap과 initial focus가 명확히 보이지 않습니다.
- Esc 닫기 동작은 코드상 확인되지 않았습니다.
- 보드 셀은 버튼이지만 게임판 의미를 더 잘 설명하는 ARIA 구조가 필요합니다.
- 전역 `::selection` 투명 처리와 텍스트 cursor 제거는 접근성에 이득이 적습니다.
- `prefers-reduced-motion` 대응이 필요합니다.

### 권장 체크리스트

- [ ] 모달 열림 시 첫 선택 카드/닫기 버튼으로 focus 이동
- [ ] Tab이 모달 밖으로 빠져나가지 않도록 focus trap
- [ ] Esc로 닫을 수 있는 모달과 닫히면 안 되는 보상 모달 구분
- [ ] 모든 hover tooltip은 focus와 touch에서도 접근 가능
- [ ] 보드 셀 상태를 스크린리더가 이해할 수 있게 라벨 개선
- [ ] reduced motion에서 burst, pop, translate 애니메이션 축소

## 7. 반응형 평가

### 현재 구조

- 넓은 화면: 3열 레이아웃입니다.
- 1520px 이하: 단일 620px 열로 접히며 보조 패널들이 위아래로 이동합니다.
- 720px 이하: 보상 카드가 1열로 전환됩니다.
- 520px 이하: 덱 빌더 컬럼이 1열로 전환됩니다.
- 460px 이하: 트레이/덱 버튼 크기가 줄어듭니다.

### 평가

반응형 분기는 존재하지만, 실제 사용성 기준으로는 **모바일에서 정보 순서 재조정이 더 중요**합니다. 작은 화면에서 보드 전에 증강/아이템이 먼저 길게 나오면 플레이 시작성이 떨어집니다.

### 권장 모바일 순서

```text
1. 현재 점수 / Best
2. 보드
3. 블록 트레이
4. 아이템 3칸
5. 증강 요약
6. 덱 / 설정
```

### 권장 규칙

- 보드와 트레이는 모바일 첫 화면에서 최대한 같이 보여야 합니다.
- 증강 상세는 접어둡니다.
- 덱 보기 버튼은 하단 보조 액션으로 낮춥니다.
- 터치 타겟은 최소 44px 이상을 유지합니다.

## 8. "게임 중 불편함" 관점 평가

### 불편 가능성이 낮은 부분

- 보드와 트레이가 가까워 반복 조작이 쉽습니다.
- 배치 미리보기와 예상 점수가 있어 실수 가능성이 낮습니다.
- 게임오버 직전 자동 undo가 있어 좌절감을 줄입니다.
- 보상 모달이 선택 순간을 명확히 끊어 줍니다.

### 불편 가능성이 있는 부분

| 위험 | 이유 | 개선 |
| --- | --- | --- |
| 선택 취소 발견성 낮음 | 선택한 조각이 트레이에서 사라져 보임 | 선택 슬롯 placeholder 유지 |
| 터치 조작 불명확 | hover 중심 미리보기/tooltip | 탭 고정 설명과 상태 문구 추가 |
| 보조 패널 과밀 | 증강/아이템/덱이 동시에 보임 | 증강 접힘, 덱 버튼 축소 |
| 재시작 오조작 | 설정 모달에서 즉시 실행 가능 | 재시작 확인 또는 hold-to-confirm |
| 비활성 이유 부족 | disabled만 보이는 경우 | 짧은 inline reason 제공 |
| 모션 피로 | combo/clear burst 반복 | reduced motion 대응 |

## 9. "한눈에 원하는 것을 유도하는가" 평가

### 시작 화면

유도성: **좋음**

플레이어가 해야 할 일은 명확합니다. 저장 게임이 있으면 이어하기, 없으면 새 게임입니다. 덱 구성도 보조 행동으로 잘 배치되어 있습니다.

개선하면 좋은 점은 비활성 새 게임 조건을 화면상에 직접 보여주는 것입니다.

### 플레이 화면

유도성: **보통 이상**

보드와 트레이는 바로 보입니다. 퍼즐 게임 경험이 있는 사용자는 즉시 조작할 수 있습니다.

하지만 완전 초보자에게는 "블록을 먼저 선택해야 하는지, 보드를 먼저 눌러야 하는지, 아이템은 언제 쓰는지"가 첫 10초 안에 완전히 명확하지 않을 수 있습니다. 첫 게임에서만 짧은 상태 안내가 있으면 해결됩니다.

권장 첫 플레이 힌트:

```text
블록을 선택한 뒤 보드에 배치하세요.
```

선택 후 힌트:

```text
놓을 칸을 고르세요. 빈 트레이를 누르면 선택이 풀립니다.
```

### 보상 화면

유도성: **좋음**

3개 중 1개 선택은 명확합니다. 다만 효과 문구를 더 수치 중심으로 압축하면 선택 속도가 빨라집니다.

## 10. 우선순위별 개선안

## P0: 바로 고치면 체감이 큰 항목

1. **모바일 정보 순서 조정**
   - 보드와 트레이가 먼저 보이게 합니다.
   - 증강 패널은 접힘 또는 요약으로 낮춥니다.

2. **선택 상태와 선택 취소 표시 강화**
   - 선택된 트레이 슬롯에 빈칸 대신 outline/ghost를 남깁니다.
   - 빈 슬롯 클릭 취소를 시각적으로 암시합니다.

3. **덱 보기 버튼 강조 낮추기**
   - 큰 세로 버튼 대신 아이콘+짧은 라벨의 보조 버튼으로 줄입니다.
   - 아이템과 같은 중요도로 보이지 않게 합니다.

4. **disabled 이유 표시**
   - 새 게임 비활성, undo 비활성, 덱 추가 불가 상태는 짧은 문구로 이유를 보여줍니다.

## P1: 품질을 올리는 항목

1. **색상 위계 정리**
   - 보드: 가장 진한 표면
   - 트레이/아이템: 중간 표면
   - 보조 패널: 더 평평한 표면
   - CTA: 제한적으로 강한 accent

2. **키보드/모달 접근성 보강**
   - focus trap
   - initial focus
   - Esc 정책
   - focus-visible 공통 스타일

3. **reduced motion 대응**
   - score count, combo burst, clear burst, hover translate 축소

4. **보상 카드 정보 구조 압축**
   - 제목
   - 현재/다음 레벨
   - 핵심 효과 수치
   - 짧은 설명

## P2: 추후 개선

1. **첫 플레이 온보딩**
   - 한 번만 보이는 1문장 힌트.
   - 별도 튜토리얼은 과합니다.

2. **증강/아이템 학습성 강화**
   - 아이콘만으로 어려운 기능은 탭 시 상세 고정.
   - 긴 설명은 모달보다 작은 detail panel로 처리.

3. **언어 톤 통일**
   - `Best`, `Score`, `Retry`, `Game Over`와 한국어가 섞입니다.
   - 게임 분위기에 맞춰 영어 유지 또는 한국어 통일 중 하나를 선택합니다.

## 12. 최종 판단

현재 와이어프레임은 **게임 플레이 자체를 방해하지 않는 수준으로 잘 잡혀 있습니다.** 보드와 트레이 중심 구조, 즉각적인 점수 피드백, 보상 모달, 자동 undo 같은 장치는 플레이 편의성에 도움이 됩니다.

가장 먼저 손볼 곳은 큰 재설계가 아니라 다음 네 가지입니다.

1. 모바일에서 보드/트레이 우선 노출
2. 선택 상태와 취소 방법 표시
3. 보조 패널과 덱 버튼의 시각 무게 낮추기
4. disabled/focus/reduced-motion 같은 기본 UX 보완

이 정도만 정리해도 사용자는 첫 화면에서 "시작한다", 플레이 화면에서 "블록을 놓는다", 보상 화면에서 "하나를 고른다"를 더 빠르게 이해할 수 있습니다.
