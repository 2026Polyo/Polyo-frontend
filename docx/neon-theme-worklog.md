# 네온 테마 구현 기록

## 목표와 범위

첫 번째 커스텀 테마인 네온 나이트의 외형·배치 효과·제거 효과를 구현한다.
사운드는 추후 제공할 파일을 연결할 설정만 정의하며 현재 네온 게임은 무음이다.
개발 브랜치는 `theme`이고 이번 작업에서는 커밋하지 않는다.

- 블록: 검은 내부를 가는 색상 선과 밝은 중심선이 감싼다. 넓게 번지는 광택은 줄인다.
- 배치: 칸마다 정사각 파편 9개가 360도 무작위 방향·속도·크기로 튀고 계속 작아지며 사라진다.
- 제거: 각 칸을 구성하는 5×5개의 흰 사각형이 서로 다른 시점에 줄어들고 짧게 가라앉으며 소멸한다. 파편 테두리와 멀리 흩어지는 동작은 제거한다.
- 필드: CC0 우주 이미지의 일부를 표시해 별 밀도를 낮추고 밝기·채도를 억제한다. CSS로 별을 만들지 않는다. 네온 플레이 화면의 배경·트레이·패널에도 어두운 톤을 적용한다.
- 경쟁 모드 대비: 플레이어별 테마·보드·효과를 분리한다. 경쟁 모드 자체는 이번 범위가 아니다.
- 규칙·점수·저장 형식·DB·구매·보유 테마·장착 API는 변경하지 않는다.
- 초기 4종의 동일 가격 정책은 유지한다. 공통 판매가격과 나머지 3종은 미확정이므로 기존 상점 예시 가격을 실제 정책으로 확정하지 않는다.

## 입력과 출력

- `ThemeScope.themeId`: 기본 `theme_classic`, 새 테마 `theme_neon`. 미지원 ID는 기본으로 표시.
- `Board.feedback`: 성공한 배치의 ID, 배치 칸과 제거 칸의 위치·색상.
- 출력: 보드·트레이·커서 블록에 같은 외형을 적용하고 해당 보드에만 시각 효과를 표시.
- 실제 게임의 시작 화면에서 `테마 미리보기 → 네온 나이트`를 선택한 뒤 새 게임 또는 이어하기로 확인한다.
- 이 선택은 체험용 화면 상태이며 보유·구매·서버 장착 완료를 의미하지 않는다. 기존 게임 저장값에는 추가하지 않는다.

## 파일별 책임

| 파일 | 책임 |
| --- | --- |
| `features/themes/gameThemes.ts` | 테마 ID, 색상표, 이미지 출처, 효과 종류, 사운드 설정 |
| `features/themes/boardFeedback.ts` | 배치 결과를 시각 효과 데이터로 변환, 좌표 정규화와 픽셀 이동값 |
| `components/ThemeScope.tsx` | 플레이어별 테마 컨텍스트 |
| `components/Board.tsx` | 실제 필드·블록·배경 이미지 표시 |
| `components/PieceShape.tsx` | 트레이·드래그 커서·모달 블록 외형 |
| `components/BoardEffects.tsx` | 최대 2묶음의 파편, 타이머·수명 관리 |
| `asset/theme/README.md` | 개발용 자산 관리 기록. 게임 화면에는 출처 문구 없음 |
| `styles/NeonTheme.css` | 보드와 미니 블록에 한정한 네온 외형·사각 파편 애니메이션 |
| `hooks/useReducedMotion.ts` | 시스템의 동작 줄이기 설정 구독 |
| `hooks/useGameSession.ts` | 유효한 배치 이후에만 피드백 발행, 게임 수치와 효과 분리 |
| `hooks/useGameAudio.ts` | 네온의 미제공 사운드를 재생하지 않고 기본 게임의 기존 소리를 유지 |

경쟁 화면에서는 각 플레이어의 보드·트레이를 서로 다른 `ThemeScope`에 넣는다.
외형은 각 보드·미니 블록의 `data-game-theme`로 한정하므로 기본 테마를 중첩해도 네온 스타일이 새지 않는다.
테마에 점수·게임 규칙을 넣지 않으며 플레이어의 보드 상태를 공유하지 않는다.

## 예외와 동작 조건

- 잘못된 위치·중복 호출로 배치 검증이 실패하면 파편을 만들지 않는다.
- 보드의 차이를 추측하지 않고 성공한 배치 이벤트를 사용하므로 불러오기·되돌리기를 새 배치로 오인하지 않는다.
- 이어하기·새 게임·아이템 사용 시 지난 피드백을 정리한다.
- 좌표는 중복을 제거하고 8×8 범위 안의 정수만 사용한다.
- 효과는 최대 2묶음·2200개 픽셀로 제한한다. 배치는 800ms, 제거가 포함된 묶음은 1400ms 후 정리한다. 교체·초기화·언마운트 시 타이머를 정리한다.
- 실제 제거 판정은 기존 260ms를 유지한다. 시각적인 녹는 효과는 별도의 레이어에서 마무리한다.
- 동작 줄이기 설정에서는 파편을 표시하지 않으며 제거 상태만 간단히 표시한다.
- 배경 이미지가 로드되지 않으면 검은 대체 필드로 계속 플레이한다.
- `placement`·`clear` 사운드는 `null`이고 `soundMode`는 `pending`이다. 이후 음원 파일·볼륨을 등록하고 테마용 재생기를 연결한다.

## 검증

- 테마·피드백·선택 저장 테스트 14개를 추가하여 기존 142개와 함께 총 156개 테스트가 통과했다.
- TypeScript 검사와 프로덕션 빌드 성공.
- 실제 게임에서 같은 배치의 기본/네온 결과가 점수 21점과 동일한 보드로 일치했다. 테스트 저장 데이터로 비교한 값이며 보상 코인과 무관하다.
- 실제 플레이에서 무효 배치의 효과 없음, 배치·줄 제거, 네온 무음, 홈 왕복과 이어하기, 저장 보존을 확인했다.
- 두 보드에서 상대 테마·상태가 바뀌지 않으며 배치 파편 9개/칸, 흰 제거 픽셀 25개/칸과 효과 수명 정리를 확인했다.
- 빠른 연속 배치의 최대 2묶음, 모바일 가로 넘침 없음, 동작 줄이기, 이미지 실패 대체 화면을 확인했다.
- 상점 미리보기·상세 모달에서도 검은 내부와 선명한 네온 선, 어두운 배경을 확인했다. 이미지 출처 문구는 화면에서 제거했다.
- 브라우저 페이지 오류 없음. 실제 경쟁 서버와 장착·구매 API는 미연결이다.

## 문제와 해결

- 기존 피드백을 유지한 채 화면을 다시 열면 지난 효과가 재생될 수 있어 이어하기 전에 피드백을 비운다.
- 사용자 게임 코드를 넓게 포맷하지 않도록 세션·플레이 화면·오디오의 수정 범위를 테마 연결 부분으로 줄였다.
- 검증용 비교 화면·임시 데이터와 캡처는 Git에서 제외된 `tmp`에 두었다. 실제 소스에는 테스트용 게임 상태를 삽입하지 않았다.

## 배경 이미지

Stars - parallax backgrounds의 CC0 이미지로 교체했다. 기존 CC BY 사진과 화면 출처 컴포넌트는 제거했다.
개발용 자산 기록·해시와 이용 조건은 `src/asset/theme/README.md`를 참고한다.

## 효과 조정과 추가 검증

- 게임의 `Math.random`과 분리된 난수 생성기로 효과를 만든다. 브라우저 난수로 시드를 정하고 효과 시작 시 한 번 생성해 같은 효과의 재렌더링에서는 값이 바뀌지 않는다.
- 배치 속도는 45~145px/s, 크기는 2~5.5px, 수명은 360~580ms 범위다. 방향은 0~360도 전체에서 선택한다.
- 제거 픽셀은 흰색으로 밝아진 뒤 작아진다. 6~20px 아래로만 흘러 큰 조각이 분리되는 인상을 줄인다. 지연을 포함해 800ms 안에 종료한다.
- 브라우저에서 비행 초반·중간·끝의 크기 감소, 다음 배치 시 기존 효과의 값 유지, 흰 사각형의 축소를 확인했다.
- 배경 변경과 톤 조정 뒤 실제 게임에서 기본/네온의 저장 보드와 21점 결과가 일치했다. 무효 배치, 이어하기, 모바일, 동작 줄이기, 이미지 실패와 큐 정리도 확인했다.
- 테스트 152개, 타입 검사, 배포 빌드 통과. 브라우저 오류 없음. 소리는 계속 추후 연결할 설정만 유지한다.

## 배치 시작점 조정

- 중앙 30~70% 영역에서 시작하던 파편을 블록 밖의 원 둘레로 옮겼다. 시작 반지름은 칸 너비의 76~80%이며, 파편의 중심을 해당 위치에 맞춘다.
- 원 둘레의 9개 구간에 각도 흔들림과 전체 회전을 적용해 원형 분포와 매번 다른 모양을 함께 유지한다. 각 파편은 시작점의 반지름 방향으로 더 멀어진다.
- 속도·크기·수명과 축소 동작, 제거 효과는 유지한다.
- 모바일 모서리 배치에서 필드 밖 파편이 가로 넘침을 유발해 효과 레이어의 표시 범위를 필드 경계로 제한했다.
- 152개 테스트와 타입 검사 통과. 브라우저에서 9개 파편 모두 블록 밖에서 바깥 방향으로 출발함을 확인했고, 모바일 활성 효과의 가로 넘침 없음과 크기 감소·난수 값 유지도 확인했다.

## 아래에서 위로 녹는 제거 효과

- 흰색 전환은 기존 약 60ms에서 약 236~274ms로 늘렸다. 각 픽셀의 지연 이후 검은색에서 흰색으로 천천히 바뀌고, 그 뒤 작아지며 가라앉는다.
- 블록마다 아래쪽 시작 지점과 시작 시간을 다르게 정한다. 다음 줄의 각 픽셀은 아래·대각선 아래 이웃 중 가장 먼저 도달한 시간에 70~110ms를 더해 시작한다. 따라서 위로 연결되는 불규칙한 진행 경로가 생긴다.
- 5×5 배열을 아래부터 한 번만 순회한다. 칸당 O(25) 계산·저장이며 탐색 큐·정렬·프레임별 JavaScript 처리는 사용하지 않는다. 같은 효과를 다시 렌더링해도 경로를 새로 계산하지 않는다.
- 픽셀 수는 25개/칸으로 유지한다. 진행 중인 칸은 `memo`로 재사용하고, 제거 픽셀의 흐림 그림자를 없앴다.
- 동시 최대 2묶음·2200픽셀을 초과하면 오래된 효과와 타이머를 먼저 정리한다. 최대 64칸을 연속 제거하는 검증에서는 1600개만 유지됐고 수명 후 모두 제거됐다.
- 제거 시각 효과는 최대 1400ms 안에 끝나지만 실제 게임 제거 판정은 기존 260ms를 유지한다. 배치 효과는 기존 800ms 정리를 유지한다.
- 브라우저에서 8개 제거 칸의 서로 다른 경로, 느린 흰색 전환, 흰색 전환 뒤 축소, 260ms 이후 게임 판정 완료와 시각 효과 지속을 확인했다.
- 로컬 브라우저에서 64칸(1600픽셀) 효과 데이터를 만드는 계산을 100회 측정한 중앙값은 약 0.2ms, 95백분위는 약 0.6ms였다. 이는 데이터 생성 시간이며 실제 렌더링 FPS나 저사양 모바일 성능을 보장하는 값은 아니다.
- 전체 153개 테스트, 타입 검사, 배포 빌드 통과. 모바일·동작 줄이기·이미지 실패·큐 정리와 실제 게임의 저장·점수·복귀 동작도 재검증했다.
- 변경 파일: `features/themes/boardFeedback.ts`, `components/BoardEffects.tsx`, `styles/NeonTheme.css`, 테마 테스트와 이 기록. 구매·DB·사운드·점수 로직은 수정하지 않는다.

## 원래 블록을 보존하며 녹이기

- 이전에는 실제 제거 칸을 숨긴 뒤 검은 작은 조각만 표시해 네온 외곽이 먼저 사라졌다. 각 조각이 원래 타일 외곽의 해당 부분을 함께 보유하도록 바꿨다.
- 위·아래·좌·우 가장자리 조각에만 기존 네온 선을 그린다. 내부 조각에는 선을 추가하지 않으며 네 귀퉁이의 둥근 모양도 유지한다.
- 시작 전에는 25개 조각이 원래 검은 내부와 연속된 네온 외곽을 구성한다. 아래에서 시작한 전파가 도착한 조각만 내부와 외곽 색을 흰색으로 바꾸고 줄어들며 사라진다. 위쪽의 녹지 않은 외곽은 그대로 남는다.
- 조각마다 새 요소나 추가 애니메이션을 만들지 않는다. 기존 25개 요소의 경계 스타일과 색상만 사용하며, 흐림 없는 안쪽 선으로 표현한다. 기존 경로 사전 계산·메모이제이션·2200픽셀 제한을 유지한다.
- 브라우저에서 효과 시작 시 25개 모두 검은 내부·불투명 상태임을 확인했다. 외곽 16개에만 테두리가 있고, 녹는 중에도 위쪽의 원래 검은 블록과 아래쪽의 흰 조각이 함께 보였다. 효과 수명 후 모두 정리됐다.
- 테스트 153개·타입 검사·배포 빌드 통과. 변경 범위는 `BoardEffects.tsx`의 외곽 분할 표시와 `NeonTheme.css`의 해당 스타일이며 게임 판정·경로 계산·배치 효과는 유지한다.

## 미리보기에서 실제 게임으로 연결 및 별 가독성 개선

- 체험 화면의 `게임으로` 링크가 단순히 홈으로 이동해 네온 선택을 전달하지 않았고, 홈의 선택도 앱 상태에만 있어 새로고침하면 기본으로 복귀했다. 상점 상세는 외형 표시만 제공하고 있었다.
- `themePreview.ts`와 `useThemePreview.ts`를 추가했다. `polyomino-preview-theme`에 미리보기 선택만 별도 저장하며, 잘못된 값·저장소 차단은 기본 테마로 안전하게 처리한다. 선택 저장이 실패해도 현재 화면에서 테마 선택은 유지한다. 다른 탭의 선택 변경도 동기화한다.
- 체험 화면의 이동 링크는 네온 선택을 기록한 뒤 홈으로 이동한다. 이 비교 화면은 계속 Git에서 제외된 `tmp`에만 둔다.
- 상점 상세에 `게임 미리보기로 선택` 버튼을 추가해 홈의 선택으로 전달한다. 게임 외형을 구현한 기본·네온만 선택할 수 있고, 나머지는 준비 중으로 표시한다. 실제 구매·보유·장착 API는 호출하지 않는다.
- 네온 게임의 새 게임·이어하기는 기존 선택을 전달받는 구조를 유지한다. 저장된 게임 진행 정보에는 테마를 삽입하거나 덮어쓰지 않는다.
- 배경을 검은 여백과 눈에 띄는 큰 별이 있는 Starfield 7 이미지로 교체했다. 원본의 일부를 표시해 별 개수를 줄이고, 밝기를 낮추던 필터를 제거해 불투명도 0.86으로 표시한다. 새 파일은 95383 bytes로 이전 231335 bytes보다 작다. 개발용 자산 기록은 `asset/theme/README.md`에 갱신했고 게임 화면에 출처 문구는 없다.
- 검증: 체험 링크→홈→새 게임, 상점 선택→홈→새 게임, 새로고침→이어하기, 보드·트레이 네온 적용, 탭 간 선택 동기화, 저장소 차단, 미지원 테마 비활성화를 실제 브라우저에서 확인했다. 기존 게임 보드·트레이·점수가 유지됐다.
- 이어하기 검증의 문자열 비교는 기존 저장 파서가 객체 키 순서를 정리하는 것까지 변경으로 오인했다. 실제 데이터 값을 비교해 진행 상태가 동일함을 확인했다. 이미지 실패 검증은 Vite의 이미지 모듈 요청과 실제 이미지 요청을 구분하도록 수정했다.
- 전체 156개 테스트·타입 검사·배포 빌드 통과. 기존 효과·동작 줄이기·이미지 실패 대체·모바일 가로 넘침·홈 왕복을 재검증했고, 기존/네온 게임의 동일 배치가 동일한 21점 결과와 보드를 유지했다.

## 블록 불룸과 필드 네온 경계

- 네온 블록의 선명한 중심선은 유지하면서 색상별 5px·14px의 바깥 발광과 약한 안쪽 빛을 추가했다. 보드·트레이·드래그 블록은 기존 공통 선택자를 통해 같은 외형을 사용한다.
- 필드의 기존 1px 테두리를 밝은 청록색으로 바꾸고 주변 빛을 더했다. 테두리 두께와 보드 크기는 유지해 칸 위치·배치 좌표에 영향을 주지 않는다.
- 상점의 네온 상품 미리보기에도 동일한 블록 발광과 필드 경계를 적용했다. 기본 테마는 변경하지 않는다.
- 정적인 CSS 그림자로 처리해 DOM·타이머·프레임별 계산을 추가하지 않았다. 작은 제거 픽셀마다 추가 흐림을 넣지 않아 기존 효과 상한과 제거 경로를 유지한다.
- 데스크톱·모바일 캡처에서 발광과 필드 경계를 확인했다. 가로 넘침·기본 테마 격리·배치/제거 정리·동작 줄이기·이미지 실패 대체 검증 통과. 녹는 중 원래 외곽 유지도 확인했다.
- 타입 검사·배포 빌드 통과. 이번 변경은 `NeonTheme.css`·`ShopScreen.css`와 이 기록에 한정된다.

## 필드 경계의 직선 펄스

- 필드의 청록색 연결 테두리와 주변 발광을 제거했다. 필드 곡률은 블록과 같은 3px로 낮췄으며, 기존 1px 경계 공간은 투명하게 유지해 보드 좌표·크기를 바꾸지 않는다.
- 모서리에서 연결되지 않는 상하좌우 1px 흰 직선 네 개를 표시한다. 실제 보드는 양 끝 12px씩, 작은 상품 미리보기는 8px씩 띄운다.
- 4.2초 주기로 불투명도 0.2~0.5 사이를 천천히 왕복한다. 화면 전체나 블록 색은 변하지 않는다. 동작 줄이기 설정에서는 펄스를 끄고 불투명도 0.32로 고정한다.
- 의사 요소 하나에 네 선을 그려 추가 DOM·JavaScript 타이머 없이 처리한다. 클릭을 가로채지 않으며 기존 블록 불룸은 유지한다. 상점 네온 미리보기도 같은 선과 펄스를 사용한다.
- 브라우저에서 밝기 최저·최고 값, 흰 직선 네 개, 작은 곡률, 기본 테마 격리, 배치 클릭, 모바일 가로 넘침 없음, 동작 줄이기와 상점 표시를 확인했다.
- 타입 검사와 배포 빌드 통과. 이번 변경은 `NeonTheme.css`·`ShopScreen.css`와 이 기록에 한정한다.

## 네온 나이트 상품 설명 수정

- 사용자 승인 문구인 ‘어둠 속에서 더 선명하게. 고요한 우주를 밝히는 네온으로, 나만의 보드를 완성하세요.’로 설명을 교체했다.
- `themePresentation.ts`의 공통 설명만 수정해 상품 카드와 상세 모달에 함께 반영한다.
- 다른 테마와 게임 기능은 변경하지 않는다. 두 화면이 같은 설명을 사용하는 것을 확인했다.

## 후보 2번 고해상도 사진 적용과 주 피사체 구도

- 사용자가 승인한 후보 2번의 원본 JPEG(5730×3910)를 적용하고 이전 PNG를 제거했다. 사진을 정사각형으로 변형하거나 작은 이미지를 확대한 파일로 대체하지 않았다.
- `gameThemes.ts`에 원본 초점·화면 위치·표시 높이를 정의했다. 사진의 (67%, 39.5%) 지점을 필드의 (42%, 40%)에 고정하며 높이는 160%, 너비는 자동으로 원본 비율을 유지한다.
- `ThemeFieldBackground.tsx`를 추가해 실제 보드와 상점 미리보기가 같은 표시 방식을 재사용한다. 필드 밖 사진만 잘라내고 이미지 실패 시 기존 검은 대체 필드를 유지한다.
- 큰 보랏빛 부분이 처음 구도에서는 상점 예시 블록에 가려져 화면 초점을 왼쪽으로 조정했다. 예시 배치와 게임 규칙은 바꾸지 않았다.
- PC·모바일·상점·실제 새 게임에서 이미지 자연 크기 5730×3910, 표시 비율 약 1.46547, 초점 위치 (42%, 40%)와 필드 빈틈 없음·가로 넘침 없음을 확인했다. 2배 픽셀 밀도에서도 캡처해 확인했다.
- 전체 156개 테스트·타입 검사 통과. 배포 빌드 성공. 기존 파편·녹기·흰 경계 펄스·블록 불룸과 점수·저장 형식은 유지한다.
- 원본과 라이선스 관리 기록을 `asset/theme/README.md`에 갱신했다. 게임 화면에 출처 문구는 추가하지 않는다.
