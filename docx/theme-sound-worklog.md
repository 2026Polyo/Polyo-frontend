# 젤리·마인크래프트·고양이 사운드 — 2026-11-05

> 현재 Minecraft는 아래의 초기 합성 시안에서 Java 1.21.1 원본 음원으로 교체되었다. 변경 이유와 최신 검증은 문서 마지막의 원본 음원 교체 항목을 따른다.

## 목표·수정 범위

네온에 이어 나머지 세 테마의 배치·제거 사운드를 구현한다. React·TypeScript·Vite와 기존 `useThemeAudio`·플레이어별 공유 AudioContext를 재사용했다. 공통 버튼·팝업·게임오버·제거 보이스·콤보, 점수·판정·260ms 게임 제거 처리와 저장 형식은 유지했다.

입력은 성공한 배치의 실제 조각 색상, 제거 줄 수, 제거 직전 셀 스냅샷이다. 출력은 테마별 배치음, 제거음과 필요한 예약 음이다. 무효 배치·호버·불러오기는 새 재생 요청을 만들지 않는다. `createBoardFeedback`을 한 번 만들어 시각 효과와 소리가 같은 제거 색상을 사용한다.

## 테마별 결과

- 젤리팝: 0.19초 배치음 3종, 0.32초 제거음 2종. 낮고 둥근 탄성음을 중심으로 만들고 제거 시의 마찰 질감만 약하게 추가했다. 긴 젖은 소리나 강한 고주파를 피하도록 조정했다. 음량은 배치 0.42·제거 0.38이다.
- 고양이 드림: 약 0.29~0.5초의 합성 울음 6종. 기본 음높이·길이·상승/하강 억양이 다르다. 플레이어별 섞기 주머니를 사용해 모든 변형을 순환하되 직전 울음이 다음 주머니 경계에서도 바로 반복되지 않는다. 제거음은 약 0.34초의 부드러운 낮은 음이다.
- 마인크래프트: 18개 블록의 재질을 아래 조사표로 구분한다. 각 배치에 해당 재질음을 사용한다. 제거는 균열 중의 짧은 채굴음, 360ms+타일 파동 지연의 파괴음, 아이템 회전이 끝나는 1720ms의 획득음으로 이어진다. 획득음은 경험치 차임이 아닌 짧은 pop 성격으로 만들었다.

추가한 소리는 게임 원본 녹음을 복사한 파일이 아니라 직접 만든 PCM 합성 시안이다. Minecraft는 Mojang의 공개 Bedrock 리소스 팩에 있는 재질·이벤트 정의를 레퍼런스로 삼았다. 현재 시각 텍스처는 Java 기반이며 원본 Java 녹음을 그대로 재현했다고 주장하지 않는다. 음색과 기분에 관한 평가는 사용자 청음 후 조정한다.

## 공통 처리·예외·성능

- 재질별 버퍼와 변형을 해당 플레이어의 테마 초기화에서 한 번 만든다. 게임 실행 중 새 사운드 파일 다운로드는 없다. 기존 공통 음원 로더의 오류 처리와 컨텍스트 공유를 유지했다.
- PCM은 유효 샘플레이트를 검사하고 진폭을 0.65 이내로 제한한다. 시작·끝 페이드를 적용하고 최초·마지막 샘플을 0으로 맞췄다.
- 배치 동시 소리는 2개, 일반 테마의 제거 묶음은 1개, Minecraft 제거 묶음은 2개로 제한한다. Minecraft 제거는 12개 재질당 hit/break와 획득음 1개, 최대 25개 예약이다. 재질 수에 따라 개별 gain을 나눠 소리를 겹친다.
- Web Audio의 source.start 시간으로 예약하며 JS 타이머를 추가하지 않았다. 묶음 중지 시 아직 시작하지 않은 획득음도 취소한다. 보통 배치로 앞선 Minecraft 아이템 획득음을 끊지 않는다.
- 랜덤 선택은 게임용 Math.random을 사용하지 않는다. 주머니·버퍼·예약은 플레이어별로 분리한다. 테마 전환·홈 복귀·언마운트 시 테마의 소리만 정리하며 공통음은 유지한다.
- 고양이의 느린 포먼트 가중치는 16샘플마다 갱신하고 배음을 점화식으로 계산한다. 배열을 샘플마다 할당하지 않는다. 재질별 고정 필터 계수도 합성 루프 밖에서 계산한다.

## 젤리 음색 조정 — 저음 편중 개선

- 사용자 청음 결과 재생은 되지만 저음과 작은 크기 때문에 잘 들리지 않는 것으로 확인했다. 다른 테마·공통 오디오 라우팅은 유지하고 젤리 PCM과 재생 gain만 수정했다.
- 기존 95Hz대 중심에서 310~330Hz대 중심으로 올리고, 짧은 하강 어택·감쇠하는 탄성 떨림·중고음 배음을 추가했다. 강한 젖은 잡음은 추가하지 않았다.
- 배치 수명은 0.19→0.23초, 제거는 0.32→0.34초로 조정했다. 재생 gain은 배치 0.42→0.52, 제거 0.38→0.48로 올렸다. 두 배치와 한 제거의 동시 재생 상한과 PCM 진폭 제한은 유지했다.
- 작은 스피커 청취의 근사 지표로 실제 gain을 적용한 PCM의 450Hz 고역 통과 RMS와 전체 에너지 비율을 검사하는 회귀 테스트를 추가했다. 모든 젤리 변형에서 고역 통과 RMS 0.03 초과·에너지 비율 22% 초과를 확인한다. 실제 기기의 주관적 청취 품질을 이 수치만으로 보장하지는 않는다.
- 전체 테스트 226개, 타입 검사·빌드 통과. 미리듣기 화면에서 배치·제거를 재생해 오디오 running 상태·출력 파형·오류 로그 없음을 확인했다.
- 개선된 비교용 파일은 `output/audio/jelly-sequence-v2.wav`이며 실제 게임의 PCM·gain으로 출력했다. 원래 시안은 보존했다.

## 젤리 제거음 분리 — 참격과 파편 소리

- 제거음이 배치음과 비슷하고 시각 참격 시작 전에 끝나던 부분을 수정했다. 최근 개선한 배치음과 다른 세 테마·공통 효과음은 유지했다.
- 제거 전용 `jellyClearSound.ts`를 추가했다. 시각 효과의 `JELLY_SLASH_MS`(320ms)에 약한 대역 제한 스와이프, `JELLY_BREAK_MS`(440ms)부터 서로 다른 높이의 부드러운 파편음 세 개를 합성한다. 전체 길이는 약 740ms이며 제거 연출 수명 안에 끝난다.
- 젖은 잡음과 날카로운 금속 참격음 대신 짧은 바람 질감과 중음역 탄성음을 사용한다. 기존 제거 gain 0.48과 PCM 진폭 0.65 상한을 유지했다.
- 젤리 제거 묶음을 최대 두 개까지 유지한다. 빠른 후속 제거가 320ms 참격 전에 앞선 제거음을 끊지 않도록 했으며, 세 번째 묶음에서는 가장 오래된 것을 정리한다. 테마 전환·홈 복귀 시 두 묶음 모두 정리한다. 추가 JS 타이머는 없다.
- 회귀 테스트로 참격 전 무음, 참격·파편 시점의 유효 파형, 연속 제거 묶음 보존·정리를 확인했다. 청취성 검사는 의도적인 연출 대기 시간을 제외한 실제 재생 구간을 검사한다.
- 전체 228개 테스트, 타입 검사와 빌드 통과. 청음용 `output/audio/jelly-clear-v3.wav`는 실제 게임 PCM과 gain으로 출력했으며 커밋에서 제외한다.

### 목표·입출력·수정 범위

재질을 구분한 합성 시안이 원작의 설치 효과음과 다르게 들리는 문제를 해결했다. 입력은 기존 조각 색상과 제거 직전 셀 스냅샷이며, 출력은 해당 재질의 Java Edition 1.21.1 원본 설치·채굴·파괴·획득음이다. 18개 블록→12개 재질 매핑과 기존 시각 효과 예약 시점, 다른 테마와 공통 효과음은 유지한다.

### 변경 내용과 레퍼런스

- 원본 sounds.json의 37개 이벤트에서 앞 두 변형을 선택하고 공유 파일을 중복 제거해 Ogg Vorbis 45개를 포함했다. 합성 Minecraft 코드는 제거했다. 원본 바이트를 약 680kB의 로컬 자산 하나로 묶어 재인코딩하지 않고 각각 디코딩한다.
- 소스는 InventivetalentDev/minecraft-assets의 1.21.1 자료이며 커밋 aef047f783f44424a591eeecf6b230d5bb0c8095로 고정했다. sounds.json의 URL·해시와 개별 원본의 Git blob SHA-1·SHA-256은 src/asset/sound/minecraft/provenance.json에 기록했다. 미러 제공 자체를 사용 허가로 간주하지 않는다.
- 돌·금속·유리의 설치음은 원작 정의대로 dig/stone을 공유한다. 일반 배치는 재생 속도 0.8, 금속은 1.2로 구분한다. 바다 랜턴은 설치 시 돌 계열, 파괴 시 유리 계열이다. 슬라임·벌집·균사·사마귀·벚나무·이끼·자수정·TNT·양털은 각 이벤트의 원본을 선택한다. 원본 이벤트별 volume·pitch도 적용한다.
- 기본 재생 이득은 배치 0.46·제거 0.4를 유지했다. 획득음은 random/pop이며 재생 속도 2로 연결했다. 모든 원작의 거리 감쇠·환경·무작위 피치까지 재현하는 범위는 아니다.
- 컨텍스트별 읽기 전용 디코딩 캐시와 최대 4개 병렬 디코딩을 사용한다. 테마 선택 시 게임 진입 전에 미리 로딩한다. 상대 플레이어와 변형 선택·예약 묶음·중지 상태를 공유하지 않는다.

### 예외·발생한 문제와 해결

- 로딩 중에는 이벤트별 최신 요청만 보관하고 250ms가 넘으면 버린다. 로딩 완료나 오디오 재개 순서에 관계없이 신선한 요청만 재생한다. 테마 전환·홈 복귀에서는 대기·예약 소리를 취소한다.
- 음원 읽기·디코딩 실패는 게임 로직과 공통 소리를 막지 않는다. 실패한 캐시는 제거하여 다음 로딩 때 재시도한다. 파일이 없을 때 합성 모사음으로 조용히 대체하지 않는다.
- 원본 메타데이터 서버 연결이 실패해 고정 커밋의 자산 미러를 사용하고 Ogg 헤더·원본 파일 크기·Git blob 해시를 검증했다.
- 테스트 실행 시 샌드박스 임시 폴더 rename 권한 오류가 발생해 TEMP·TMP를 무시되는 tmp/vitest로 지정했다.
- 파일·해시 검사용 테스트에 @types/node 개발 의존성을 추가했다. 이로 인해 브라우저 점수판 타이머가 Node Timeout으로 추론되는 타입 충돌을 발견해 실제 window.setInterval의 반환값인 number로 명시했다. 실행 로직은 동일하다.

- 전체 24개 파일·232개 테스트 통과. TypeScript 검사와 Vite 배포 빌드 통과. 원본 음원이 배포 자산으로 포함되는 것을 확인했다.
- 18개 색상의 실제 원본 경로·피치·이벤트 볼륨, 45개 Ogg 원본 해시, 인덱스 범위, 컨텍스트별 중복 로딩 방지와 디코딩 병렬 상한, 로딩 실패 후 재시도를 검사했다.
- 브라우저 미리듣기에서 다이아몬드·슬라임·벚나무·자수정·양털의 버퍼와 재생 속도, 비영 출력 파형, 혼합 제거의 채굴→파괴→획득 예약을 확인했다. 테마 정지 후에도 공통 버튼음이 재생되며 젤리팝 배치·제거도 유지된다. 콘솔 오류·경고는 없었다.
- 브라우저 검증은 실제 게임과 같은 useThemeAudio를 사용하는 작업용 화면에서 수행했다. 실제 게임 전체 플레이를 자동화한 검증은 아니다. 취향에 따른 최종 음량 평가는 사용자 청음이 필요하다.
- tmp/의 미리듣기 화면은 커밋 대상에서 제외한다. 원본 정보는 내부 문서에만 기록하며 게임 화면에 출처 문구는 추가하지 않았다.

## 고양이 배치음 개선 — 녹음 5종 적용

- 목표와 범위: 성공한 고양이 드림 블록 배치마다 밝고 짧은 울음 하나를 재생한다. 기존 제거음, 다른 테마, 공통 효과음과 게임 규칙은 유지했다.
- 레퍼런스와 편집: BigSoundBank의 CC0 고양이 녹음 5종을 사용했다. 원본 WAV의 앞뒤 무음을 줄이고 짧은 페이드와 음량 보정을 적용했다. 0.43~0.82초의 단일 채널 WAV를 1.10배 속도로 재생한다. 원본 페이지·라이선스·해시와 편집 결과는 src/asset/sound/cat에 기록했다.
- 구현: 파일 변형을 기존 플레이어별 무작위 선택 방식에 연결했다. 다섯 음원을 한 번씩 섞어 재생한 뒤 다시 섞으며 직전 울음은 반복하지 않는다. 시작 화면에서 미리 불러오며 같은 AudioContext 안에서 이미 디코딩된 파일을 재사용한다.
- 예외: 일부 파일을 불러오지 못하면 정상 파일만 사용한다. 실패한 캐시는 다음 로딩 때 재시도할 수 있게 비운다. 로딩 중 최신 배치만 250ms까지 보관하며, 오래된 요청과 테마 전환 뒤 요청은 재생하지 않는다. 파일을 모두 못 읽어도 게임과 제거음은 계속 작동한다.
- 검증: 전체 24개 파일, 테스트 233개 통과. 타입 검사와 배포 빌드 통과. 브라우저 미리듣기에서 5개 원본 버퍼의 첫 순환과 다음 순환의 반복 방지, 실제 Web Audio 출력, 제거음 및 공통 버튼음 재생을 확인했다.

## 고양이 배치음 교체 — 또렷한 야옹

기존 배치음이 그르릉처럼 들린다는 피드백을 받았다. BigSoundBank의 Meow Cat 녹음 10개에서 파형과 음높이 변화를 비교해 발성이 이어지는 5개를 골랐다. 각 원본에서 울음 한 번에 해당하는 구간을 0.55~1.33초로 지정하고 양끝 페이드와 음량 보정을 적용했다. 처리한 5개 WAV의 RMS는 약 0.12다. 원본 링크와 구간은 고양이 배치음 자산의 sources.json에, 결과 해시는 provenance.json에 기록했다.

일부 원본의 오디오 데이터 뒤에 비표준 메타데이터가 있어 WAV 가져오기가 중단됐다. WAV 형식과 샘플 데이터 청크를 읽고 길이를 검사한 다음 파싱을 끝내도록 수정했다. 브라우저 미리듣기에서 5종의 재생과 한 순환 경계에서의 반복 방지를 확인했다. 테스트 233개와 타입 검사 및 배포 빌드가 통과했다.

## 사용자 제공 야옹 음원으로 교체

사용자가 제공한 MP3를 고양이 드림의 배치음으로 적용했다. 원본을 한 번 불러와 −3, −1.5, 0, +1.5, +3 반음에 해당하는 재생 속도로 사용한다. 기존 무작위 순환으로 다섯 높낮이를 한 번씩 재생하고 직전 높낮이는 반복하지 않는다. 속도를 바꾸는 방식이라 낮은 음은 조금 더 길고 높은 음은 조금 더 짧다. 이전 자산과 가져오기 스크립트는 tmp/cat-pitch/previous에 보관했다.

브라우저에서 원본 버퍼 하나로 다섯 음높이가 모두 재생되는 것을 확인했다. 테스트 233개와 타입 검사 및 배포 빌드가 통과했다.
