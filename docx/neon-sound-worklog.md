# 네온 사운드 1차 — 2026-11-05

## 목표·범위·레퍼런스

네온 나이트의 성공 배치와 블록 제거에 첫 사운드 시안을 연결한다. 기존 React·TypeScript·Vite 구조와 `useGameAudio`, 테마의 `sounds` 접점, `useGameSession`의 성공 배치 이벤트를 재사용했다. 네온의 방사형 픽셀 파편과 아래에서 위로 녹는 시각 효과를 소리의 레퍼런스로 삼았다.

기본 테마의 음원과 재생 방식을 유지하고, 나머지 세 테마는 다음 단계에서 작업한다. 게임 점수·판정·260ms 제거 처리·저장 형식·백엔드는 변경하지 않았다. 이번 단계에는 배경 음악·게임오버·UI 음원 추가가 포함되지 않는다.

## 입력·출력

| 입력 | 출력 |
| --- | --- |
| 네온 테마에서 성공한 배치 | 약 0.16초의 짧은 전자음·픽셀 파편 질감 |
| 성공한 배치로 실제 블록 제거 | 약 1.12초의 작은 칩이 흩어져 녹는 하강음 1개 |
| 폭탄·특수 효과를 포함한 실제 제거 | 제거 칸 수로 확인해 같은 제거음 재생 |
| 여러 줄 동시 제거 | 중복 재생 없이 음높이를 최대 7.5% 높임 |
| 호버·미리보기·중복 클릭·불러오기 | 추가 소리 없음 |

네온 소리는 직접 합성한 원본 PCM이다. 외부 음원 파일과 다운로드 없이, 기기 샘플레이트에 맞춰 오디오 컨텍스트당 두 버퍼를 한 번 생성한다. 작은 의사 난수 발생기로 소리 질감을 만들며 게임용 `Math.random`을 소비하지 않는다. 짧은 시작/끝 페이드로 클릭을 줄이고 배치 0.28·제거 0.32의 재생 이득을 적용했다.

## 예외·성능·역할 분리

- 활성 소리는 배치 2개·제거 1개로 제한한다. 초과 요청은 같은 이벤트의 가장 오래된 소리를 정리한다.
- 사용자 동작이 필요한 브라우저에서는 컨텍스트 재개를 시도한다. 대기 요청은 이벤트당 최신 1개만 보관하고 250ms가 지난 요청은 재생하지 않는다.
- 재생 차단·Web Audio 미지원·파일 음원 네트워크 오류는 게임 입력을 막지 않는다. 미준비 파일을 나중에 불러와 지난 행동을 뒤늦게 재생하지 않는다.
- 각 플레이어가 버퍼·대기 요청·활성 소리를 따로 소유한다. 테마 전환·홈 복귀·언마운트 시 소리를 중지하고 컨텍스트를 닫는다.
- 1차 구현에서는 기본 테마만 기존 `useGameAudio`를 사용했으나, 아래 후속 수정에서 공통 보이스·콤보·UI 효과음을 모든 테마에 복구했다.

## 완료 조건과 검증

- 1차 구현의 현재 소스 테스트는 207개 통과했다. 당시 407개 집계에는 `tmp/git-integration/frontend`의 이전 테스트 200개가 중복 포함돼 있었다. 아래 수정에서 검사 범위를 현재 `src`로 한정했다. PCM의 유효 값·최대 진폭·시작/끝 파형·여러 샘플레이트·게임 난수 독립성, 동시 재생 제한·플레이어 분리·지연 재개·재생 차단·파일 오류를 확인했다.
- TypeScript 검사와 Vite 프로덕션 빌드 통과.
- 실제 Edge Web Audio로 저장 게임 진입·호버 시 무음, 배치 1회에 0.16초 배치음과 1.12초 제거음 각 1회, 중복 클릭 무음, 홈 복귀 시 컨텍스트 종료, 테마 변경 시 지난 음 미재생을 확인했다.
- 나머지 세 테마의 무음 유지, 기본 테마 기존 소리 재생, Web Audio 미지원 상태에서도 배치·제거가 진행되는 것을 확인했다. 브라우저 검증의 인증·점수 API는 모의 응답을 사용했다.
- 타입 검사에서 ES2020에 없는 TypedArray.at 사용을 발견해 인덱스 접근으로 고쳤다. 프로젝트의 TypeScript 대상은 유지했다.
- `output/audio/`의 WAV 시안은 실제 PCM과 재생 이득으로 출력한 청음용 파일이며 커밋 대상에서 제외한다. 음색에 대한 최종 평가는 사용자가 들어보고 조정한다.

다음 단계에서는 네온의 톤·길이·볼륨을 조정한 뒤 같은 재생 구조로 젤리·마인크래프트·고양이 순서의 음색을 작업한다.

## 후속 수정: 공통 효과음 복구

- 사용자 요구: 배치음·제거음만 테마별로 나누고, 나머지는 기본 테마와 같은 소리로 재생한다.
- 원인: 테마 모드를 기준으로 기존 오디오 전체를 비활성화했고, 새 테마의 버튼·팝업·게임오버·콤보 연결을 빈 함수로 반환했다.
- 해결: 공통 오디오는 모든 테마에서 유지한다. `routeThemeAudio`는 네온 배치음·제거음만 교체하고, 제거 보이스·콤보는 공통 처리로 전달한다. 전용 필드음 미준비 테마와 초기화 실패 시 기존 배치음을 사용한다.
- 네온 전용 컨텍스트를 게임 진입 후 새로 만들던 방식에서, 시작 화면의 클릭으로 미리 재생 허용한 공통 컨텍스트를 공유하도록 변경했다. 첫 배치음이 별도 컨텍스트의 재생 재개를 기다리는 경로를 제거했다.
- 공통 파일 로드 실패와 컨텍스트 생성 실패를 처리하며, 정리 후 늦게 완료된 디코딩이 이전 버퍼를 다시 연결하지 않도록 했다.
- `vite.config.ts`의 테스트 대상을 `src/**/*.test.{ts,tsx}`로 한정해 임시 통합 worktree 테스트 중복 집계를 방지했다.
- 테마 5개 공통 효과음·콤보 전달, 네온 필드음 중복 방지, 미준비 테마의 기본 배치음, 초기화 실패 대체 동작을 회귀 테스트 11개로 추가했다. 현재 소스 기준 전체 218개, 타입 검사와 빌드 통과.
- 5173·5188 개발 서버의 모듈 응답에서 수정된 공통 컨텍스트 연결 코드가 제공되는 것을 확인했다. 열린 Chrome 직접 확인은 Computer Use 도구가 현재 URL을 식별하지 못해 중단돼, 이 수정 후 사용자의 실제 청음 결과는 검증하지 못했다.
