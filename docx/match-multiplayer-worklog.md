# 멀티 개선 1~3단계 작업 기록 (프론트)

## 범위
- 1. 모바일 레이아웃, 2. 게임 중 이모티콘, 3. 상대 움직임(CURSOR) 표시. 게임 규칙/턴/타이머는 그대로다.
- 백엔드 요청은 `docx/match-cursor-backend-prompt.md` (CURSOR 중계만 필요, 이모티콘은 기존 EMOTE 중계 사용).

## 변경
- `features/matchGame.ts`: `MatchCursor`, `EMPTY_CURSOR`, CURSOR 메시지 파싱(row/col은 둘 다 정수 −8~7 또는 둘 다 null), `sameCursor`, `getCursorPreview`(트레이에 없는 uid는 무시, 보드 밖 칸 제외).
- `hooks/useMatchGame.ts`: `onCursor` 콜백, `sendCursor`(첫 변화 즉시, 이후 100ms 간격, 같은 값 생략, 재연결 시 초기화). CURSOR를 보낸 뒤 `INVALID_MESSAGE`가 오면 구버전 서버로 보고 전송 중단, 오류 표시 안 함.
- `screens/MatchGameScreen.tsx`: 오른쪽 위에 이모티콘 버튼(로비의 `EmotePicker`/`useEmoteBubbles`/`canSendEmote` 재사용), 내 보드·상대 카드 위 말풍선. 내 차례에 들고 있는 블록/조준 위치 전송. 상대 차례에 상대 보드에 반투명 미리보기, 트레이에서 상대가 든 블록 강조, "블록 고르는 중…" 표시. 차례가 바뀌면 상대 커서 초기화.
- `styles/MatchGameScreen.css`: 코너 버튼, 말풍선, 상대 강조, 720px 이하 압축 레이아웃(`--match-chrome` 318px).

## 문제와 해결
- 360×640에서 트레이 아래가 잘림 → 각 줄 높이를 줄이고 chrome 값을 실측해 재계산. 보드 폭 230→322px, 320×568까지 스크롤 없이 들어감.
- 모바일에서 상대 말풍선이 미니 보드를 가림 → 미니 보드 왼쪽으로 이동.

## 검증
- `npm test`(326개 통과), `npm run build` 통과.
- 가짜 소켓 임시 페이지로 320×568 / 360×640 / 390×844 / 1280×800 확인: 이모티콘 송수신, 상대 커서 미리보기·트레이 강조, 내 CURSOR 전송(null → 3,3), INVALID_MESSAGE 이후 전송 중단 확인. 임시 페이지는 삭제함.
- 실제 서버 두 명 대전은 백엔드 CURSOR 반영 후 확인 필요.

# 멀티 UI 개선 4단계: 좌우 대칭 보드 + 가로 모바일 + 차례 아닌 보드 회색

## 변경
- `screens/MatchGameScreen.tsx`: `board-layout`/상대 미니 카드 구조를 `match-arena`(내 보드 | 상대 보드, 아래 공용 트레이)로 교체. 두 보드 위에 같은 모양의 헤더(닉네임, 점수, 연결 상태). 내 점수는 `ScoreBoard` 대신 내 헤더에 표시. 차례/타이머는 위쪽 `match-topbar`. 상태 로직은 변경 없음.
- `styles/MatchGameScreen.css`: 레이아웃 부분 재작성. 보드 한 변 `--match-board` = min(560px, 가로 절반, 세로 남는 높이), 두 보드에 같은 값. 차례가 아닌 쪽(`.is-waiting`, PLAYING 중에만) 보드는 `grayscale(1) brightness(0.75)`, 200ms 전환.
- 가로 모바일(`orientation: landscape` + 높이 ≤ 540px): 트레이를 보드 오른쪽 2×3 열로, 힌트 숨김, 오류는 화면 아래 떠 있는 배너.
- 세로 모바일(폭 ≤ 720px): 두 보드 좌우 유지(각각 폭의 절반), 트레이 3×2.

## 검증
- `tsc --noEmit`, `vitest`(326개) 통과.
- 실제 CSS를 불러온 모의 DOM으로 1280×800, 844×390(보드 300px×2, 스크롤 없음), 667×375(256px×2), 390×844 확인. 실제 두 명 대전은 미확인.

# 멀티 UI 개선 5단계: 트레이 회색 → 되돌림
- 내 차례가 아닐 때 트레이를 회색으로 했다가 요청에 따라 원래 색으로 되돌림. 차례가 아닐 때 트레이는 기존처럼 블록 opacity 0.6만 적용.

# 멀티 UI 개선 6단계: 상대 보드 항상 원래 색 + MY TURN 알림
- 회색 처리는 내 보드에만(PLAYING 중 내 차례가 아닐 때). 상대 보드는 항상 원래 색, 차례 표시는 헤더 금색 밑줄만.
- 내 차례가 시작될 때(첫 턴 포함, 내 차례가 아니다가 내 차례가 된 순간) 내 보드 위에 "MY TURN"을 콤보 알림과 같은 `combo-burst` 애니메이션(940ms)으로 표시. `usePulseLabel` 재사용. 글자 크기는 보드 한 변의 16%(`.match-turn-burst`).
- 검증: `tsc --noEmit`, `vitest`(326개) 통과. 모의 DOM 844×390에서 보드 300px에 문구 폭 238px 확인.

# 멀티 UI 개선 7단계: 블록 트레이 확대
- 데스크톱: 칸 높이 104→130px, 블록 칸 14→18px. 보드 크기 계산용 `--match-chrome` 300→326px(높이 820 이하 274→300px).
- 세로 모바일(≤720px): 칸 높이 64→80px, 블록 칸 clamp(9,3vw,12)→clamp(11,3.6vw,15)px, chrome 300→316px.
- 가로 모바일: 트레이 열 폭 clamp(120,18vw,200)→clamp(150,22vw,240)px, 블록 칸 clamp(8,1.4vw,12)→clamp(10,1.6vw,14)px.
- 측정(5칸 일자 블록, 스크롤 없음): 1280×800 보드 500px·칸 157×130; 844×390 보드 300px(변화 없음)·칸 86×94; 667×375 보드 256→241px·칸 68×74; 390×844 칸 116×80.
- 문제: 667×375에서 1.7vw면 5칸 블록(65px)이 칸 안쪽(64px)보다 1px 넘침 → 1.6vw로 낮춤.

# 멀티 UI 개선 8단계: 트레이 블록 확대 + 내 차례 시작 시 보드 테두리 빛남 + MY TURN 화면 중앙
- 트레이 블록 한 칸: 데스크톱 18→21px. 세로 모바일 clamp(11,3.6vw,15)→clamp(13,4.2vw,18)px, 슬롯 높이를 세로 5칸 블록이 들어가는 `5×칸 + 16px`로. 가로 모바일 트레이 열 clamp(150,22vw,240)→clamp(170,25vw,280)px, 칸 = min(16px, ((보드 − 16) / 3 − 12) / 5).
- 문제: 처음 값으로는 세로 5칸 일자 블록(line-5-vertical)이 세로 모바일(이전 값 포함)과 667×375에서 슬롯 높이를 넘침 → 슬롯 높이와 칸 크기를 5칸 기준으로 계산하도록 바꿈.
- 내 차례 시작 시(`TURN_START_MS` = 1000ms) 내 보드에 `is-turn-start` → 테두리 금색 3px + 바깥 빛 애니메이션. 동작 줄이기 설정이면 애니메이션 없이 테두리만.
- MY TURN: 보드 안 → 화면 중앙(`position: fixed`), 글자 clamp(2.6rem, 9vw, 6rem), 1000ms 표시.
- 검증: tsc, vitest 326개 통과. 모의 DOM(가로·세로 5칸 블록 포함)으로 1280×800, 844×390, 667×375, 390×844, 360×640에서 모든 블록이 슬롯 안에 들어가고 스크롤 없음, MY TURN 중심이 화면 중앙임을 확인.
