# 개인 작업 Git 정리 — 2026-11-04

팀의 `develop`을 기준으로 기존 작업을 옮겼다. 공용 `main`·`develop`과 기존 `shop`·`credit`·`theme`의 이력은 변경하지 않았다. 기존 작업은 `backup/*-20261104` 로컬 브랜치에도 보관한다.

## 이번 PR 순서

| 순서 | 작업 브랜치 | PR 대상 | 내용 |
| --- | --- | --- | --- |
| 1 | `feature/shop` | `develop` | 상점 UI와 임시 상품 데이터 |
| 2 | `feature/credit-ui` | `feature/shop` | 재화 API 어댑터·보상 표시 컴포넌트와 상점 컴포넌트 분리 |
| 3 | `feature/block-themes` | `feature/credit-ui` | 네 가지 테마·효과·특수 블록 구분 |

기존 구현이 앞 작업에 의존하므로 PR도 같은 순서로 나눴다. 뒤 PR의 변경 목록에는 앞 PR의 코드가 중복되지 않는다. 앞 PR을 팀에서 병합한 뒤, 뒤 PR은 최신 `develop`을 반영하고 대상을 `develop`으로 바꿔 다시 확인한다. 특히 squash 병합 시 기존 커밋이 중복 표시될 수 있으므로 대상만 바꾸고 바로 병합하지 않는다. 모든 PR은 검토용 초안으로 시작한다.

## 앞으로 작업할 때

1. 새 기능은 최신 `develop`에서 기능 브랜치를 만든다. 진행 중인 기능을 수정할 때는 해당 브랜치에서 계속한다.
2. 변경 파일을 확인하고 한 기능 단위로 커밋한다. 테스트 소스는 포함하고, 임시 화면·도구·빌드 결과·개인 환경 파일은 제외한다.
3. 기능 브랜치를 push하고 `develop` 대상 PR을 작성한다. 다른 기능에 의존하면 PR 설명에 의존 관계를 적는다.
4. 팀원의 리뷰와 필요한 검증을 거쳐 병합한다. 공용 브랜치 직접 push, force push, 기존 브랜치 삭제는 별도 합의 없이 하지 않는다.

현재 후속 테마 작업은 `feature/block-themes`에서 이어간다. 별개 새 기능을 이 브랜치에서 시작하지 않는다.
