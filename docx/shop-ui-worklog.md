# 상점 UI 작업 기록 — 2026-10-21

- 목표: 기존 게임의 파란색 디자인 토큰을 사용하는 반응형 상점 UI.
- 변경: 시작 화면 진입 버튼, 상점 목록·정렬·페이지 표시, CSS 블록 테마 미리보기, 네이티브 dialog 상세 모달.
- 범위: 예시 상품 응답 어댑터만 사용. 인증, 서버 API, 실제 구매, 재화 차감, 게임 테마 적용은 미구현이며 화면에 명시.
- 기존 게임: useGameSession을 App에 유지하여 상점 왕복 시 게임 상태를 초기화하지 않음.
- 검증: TypeScript 검사 및 Vite 빌드 성공. 기존 테스트 7개 파일 105개 통과.
- 브라우저: Edge에서 상점 진입, 가격 정렬, 상세 모달, Escape 닫기, 홈 복귀, 390px 가로 넘침 없음 확인. 데스크톱·모바일 캡처 검토.
- 문제·해결: sandbox의 패키지 설치 및 테스트 임시 파일 권한 제한은 승인된 환경에서 검증. 제목 대비와 긴 화면 배경 경계는 상점 범위 CSS로 보완.
- 후속: 실제 API 계약에 맞춰 예시 어댑터 교체, 인증 상태·보유 상품·잔액 연결 후 구매 기능 구현. 현재 빈 목록·오류 UI는 제공하지만 fixture는 성공 데이터만 반환하므로 실패 경로 브라우저 검증은 별도 필요.

## ERD 반영 후 개선
- THEME의 id/name/price에 맞춰 ShopTheme DTO와 프론트 설명·색상 메타데이터 분리.
- 상품 식별을 themeId로 통일하고 코인 단위 표시, 미등록 테마 기본 미리보기 안내 추가.
- DB와 API 주소는 자동 변경하지 않음. 상세 검토는 shop-erd-review.md 참고.
- 검증: 타입 검사·빌드 성공, 8개 파일 109개 테스트 통과. Edge에서 정렬·상세·Escape·모바일 가로 넘침·홈 복귀 확인, 페이지 오류 없음.
- 실제 DB·구매·인증·테마 선택 저장은 변경하지 않음.

## 코드 정리 — 2026-10-23

- `ShopScreen`은 화면 구성, `ShopThemeCard`는 상품 카드, `ShopThemeDialog`는 상세 모달을 담당하도록 분리.
- 조회 상태·페이지·정렬·재시도는 `useShopCatalog`에서 관리. 이전 요청이 최신 결과를 덮어쓰지 않도록 유지.
- 예시 상품은 `src/mocks/shopThemes.ts`, 설명·색상은 `src/features/themePresentation.ts`로 분리.
- JSX·CSS 들여쓰기와 긴 줄을 정리. 기존 디자인·예시 안내·구매 비활성화는 유지.
- 실제 API 연결 시 `getPreviewThemes` 공급자를 교체하고 같은 조회 결과 구조를 유지하면 된다.
- 타입 검사·프로덕션 빌드·전체 프론트 테스트 134개 통과.
- 브라우저에서 상품 6개·가격 정렬·상세 모달·Escape/닫기·버튼 포커스 복원·390px 가로 넘침·홈 복귀·저장 상태 보존을 확인. 페이지 오류 없음.
