# 블록 테마 작업 안내

## 현재 범위

네온 나이트·젤리 팝·마인크래프트·고양이 드림의 외형과 시각 효과를 제공한다. 상점에서 외형을 확인하고, 로그인한 계정으로 구매한 테마를 장착할 수 있다. 네 테마 모두 `custom` 배치음·제거음을 제공한다. 버튼·팝업·게임오버·제거 보이스·콤보는 모든 테마에서 기존 공통 효과음을 사용한다.

## 수정할 때 유지할 규칙

- 테마는 점수·블록 색 데이터·배치 가능 여부·저장 형식을 바꾸지 않는다. `useGameSession`의 성공 배치에서 피드백을 만들고, 불러오기·이어하기·아이템 처리에서는 지난 피드백을 초기화한다.
- 시각 효과는 게임용 `Math.random`을 소비하지 않는다. 장식 전용 난수·안정적인 조각 식별자를 사용한다.
- 테마 사운드도 게임용 난수를 소비하지 않는다. 합성 PCM은 테마 초기화 시 만들고 Minecraft 원본은 컨텍스트별로 한 번 디코딩한다. 성공한 배치에서만 배치음과 필요한 제거음을 요청한다. 칸 개수만큼 소리를 만들지 않는다.
- 배치음에 조각의 실제 색상을, 제거음에 제거 직전 셀 스냅샷을 전달한다. Minecraft는 18색을 12개 재질로 분류하며, 제거는 각 재질당 채굴·파괴 한 쌍과 마지막 획득음 한 번으로 제한한다. 같은 재질 64칸을 64번 재생하지 않는다.
- 고양이 배치음은 녹음 하나를 다섯 높낮이로 재생한다. 플레이어마다 순서를 섞고 한 묶음이 끝나면 다시 섞되 직전 높낮이는 바로 반복하지 않는다. Minecraft 획득음은 `MINECRAFT_ITEM_END_MS`와 맞춘 Web Audio 예약이다. 배치 입력이 와도 앞선 제거는 유지하며, 테마 변경·홈 복귀·언마운트·동시 묶음 상한 초과에서는 예약까지 함께 취소한다.
- 공통음과 테마 필드음은 플레이어의 같은 오디오 컨텍스트를 사용한다. 시작 화면의 사용자 동작으로 재생을 허용하고 새 컨텍스트 생성으로 첫 필드음이 다시 차단되는 일을 줄인다. 홈 복귀·테마 전환에서는 테마 필드음만 정리하고 공통음은 유지하며, 전체 언마운트에서 컨텍스트를 닫는다. 상대 플레이어의 소리를 전역 상태로 재사용하지 않는다. 파일 한 개는 `kind: "file"`, 파일 변형 묶음은 `kind: "files"`, 합성음은 `kind: "synth"`로 정의한다.
- 기존 260ms 제거 처리는 게임에서 담당한다. 긴 시각 효과는 제거 전 스냅샷으로 끝까지 표시하며 게임 진행을 지연시키지 않는다.
- 효과는 개수와 수명을 제한하고 초기화·언마운트·동작 줄이기에서 정리한다. 동일한 피드백 ID는 설정 변경만으로 다시 재생하지 않는다.
- CSS는 `[data-game-theme]`와 전용 클래스 아래에 둔다. 필드·트레이 격자의 클릭 크기와 간격은 유지한다.
- 새 테마를 추가할 때 `GameThemeId`, 정의와 조회, 공통 타일/효과, 시작 화면 옵션, 상점 메타데이터·임시 상품을 함께 확인한다. 상점은 공통 8×8 미리보기를 쓴다.
- 특수 블록은 `data-special`로 구분한다. 네온의 내부 채움과 젤리 윤곽선은 필드·미니 타일·시각 효과에서 같은 종류 정보를 사용한다. 고양이는 일반 칸끼리만 자유롭게 합쳐지고, 특수 칸은 `specialPieceGroups`의 조각 uid가 같은 칸끼리 연결한다.
- `specialPieceGroups`는 표시 전용 좌표→조각 uid 정보다. 점수나 특수 능력 판정에는 사용하지 않는다. 현재 게임·되돌리기 저장에 포함하고 제거 후 정리한다. 중력의 프레임 이동 지도에 따라 옮겨야 한다. 원래 저장에 조각 정보가 없으면 서로 다른 특수 조각을 추측해서 합치지 않고 칸별로 분리한다.
- 이미지 자산은 `src/asset/theme/`에 포함하며 출처·파일 해시는 해당 README와 provenance를 유지한다. 게임 실행 중 원격 이미지를 가져오지 않는다.

## 상점 API 연결

`ShopTheme`는 `themeId`, `name`, `price`를 가진 조회 DTO다. 상품 이미지와 게임 외형은 API 응답의 `themeId`로 찾는다. 구매 가격, 보유 여부, 코인 차감과 장착 권한은 서버가 검증한다.

## 테마 렌더링 개선

### 제거 효과 재사용

- 네온과 마인크래프트는 이미 재생 중인 효과 묶음을 다시 렌더링하지 않는다. 젤리 팝은 기존 효과 묶음 재사용을 유지한다.
- 고양이 드림은 보드별 SVG 도형 하나를 참조한다. 5줄 제거에서 발바닥은 34개였고 효과 영역의 DOM 요소는 375개에서 181개로 줄었다. 발바닥만 같은 애니메이션 시점에 캡처한 이미지는 픽셀 단위로 일치했다.
- 배포 빌드에서 같은 5줄 제거를 테마별 3회 비교했다. 제거 효과의 개수·좌표·색상·타이밍 설정이 일치했고, 프레임 시간은 일관되게 개선되지 않았다. 프론트 테스트 353개와 Vite 빌드가 통과했다.

### 젤리 팝 5줄 제거

- 8×8 보드의 참격 범위를 행과 열의 비트로 계산해 중복 좌표 처리와 문자열 생성을 줄였다. 파편의 둥근 정도는 같은 난수 순서로 계산하며 임시 배열을 만들지 않는다. 움직이는 파편에만 합성 힌트를 준다.
- 헤드리스 Edge에서 같은 5줄 제거를 전후 5회씩 비교했다. 프레임 시간 p95 중앙값은 38.9ms에서 33.4ms로 줄었고, 33.4ms를 넘긴 프레임 수 중앙값은 10개였다. 참격과 파편의 개수·좌표·애니메이션 설정이 일치했다. 정지 화면은 픽셀 단위로 일치했고, 움직이는 파편의 가장자리는 브라우저 합성에 따라 미세한 픽셀 차이가 있었다.
- 유리 배경 분리는 프레임 이득이 일관되지 않고 테두리 색에 차이가 있어 제외했다. 프론트 테스트 353개와 Vite 빌드가 통과했다.

### 젤리 팝 배치 전 보드 렌더링

- 하드모드에서 46칸을 채우고 배치나 제거 없이 커서를 192회 움직였다. 젤리 블록의 그라데이션·그림자·반사광을 검사 중에만 껐을 때 프레임 시간 차이는 작았다.
- 공통 보드에서 칸의 색·미리보기·제거·배치 상태가 같으면 해당 칸의 React 렌더링을 건너뛴다. 입력 이벤트에는 현재 게임 상태의 핸들러를 사용한다.
- 동일한 입력에서 React가 갱신한 보드 칸은 12,288회에서 12회로 줄었다. 헤드리스 Edge 배포 빌드 4회 비교에서 브라우저 스크립트 실행 시간 중앙값은 약 193ms에서 160ms로 줄었고, 프레임 시간 개선은 뚜렷하지 않았다. 블록이 채워진 정지 화면은 픽셀 단위로 일치했다.
- 네 테마의 같은 5줄 제거에서 보드 칸의 표시와 효과 요소·설정이 일치했다. 프론트 테스트 353개와 배포 빌드를 통과했다.

### 고양이 드림 대기 블록과 제거 미리보기

- 대기 슬롯이 현재 게임 테마를 읽도록 연결해 고양이 드림의 기본 파란색 배경을 연보라색으로 바꿨다. 대기 블록은 얼굴을 키우고, 필드 밖에서 새로 표시되는 얼굴과 귀는 등장 지연을 줄였다.
- 제거 미리보기는 기존 제거 연출과 발바닥 SVG 하나를 공유한다. 배치하면 지워질 칸 위에 어두운 반투명 발바닥을 표시한다. Edge에서 대기 슬롯, 드래그 조각, 가로·세로 5줄이 겹치는 미리보기의 34칸에 발바닥이 하나씩 보이는 것을 확인했다. 테스트 354개와 빌드를 통과했다.

## 검증 방법

- 자동 검사: `npm test`
- 타입·배포 빌드: `npm run build`
- 화면 확인: `npm run dev -- --port 5188` 후 시작 화면에서 테마를 선택한다. 네 테마의 새 게임·배치·가로/세로 제거·홈 왕복·이어하기·상점 카드/상세를 확인한다.
- 모바일 폭과 OS 동작 줄이기 설정도 확인한다. 설정을 다시 켰을 때 지난 효과가 재생되면 안 된다. 고양이는 붙이기·분리 시 표정/귀 교체, 마인크래프트는 순차 채굴과 동시 소멸을 확인한다.
- 단위 검사는 `src/features/__tests__/`에 포함한다. `tmp/`의 시연 화면·로컬 검사 스크립트와 `output/` 캡처는 커밋하지 않는다.
